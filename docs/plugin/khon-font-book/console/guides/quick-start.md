# KhonFontBook 最小操作说明

适用：Halo 2.27.0 / Java 21、Linux x86_64、glibc ≥2.38、系统prlimit及可写/可执行临时目录，本地同源存储与静态单色WOFF2/TTF。解析组件随包提供，专用存储自动准备，无需填写解释器或策略；进入工作台确认实际状态。可变、颜色和集合字体暂不支持。字体来源与授权应允许当前使用，完整边界见 [用户说明](user-guide.md)。

1. 在 Console「工具 → KhonFontBook」导入 WOFF2或TTF，填写来源、授权说明与分类；也可选择专用策略中的已有附件。普通账号需授予「查看字体资源」和「管理字体资源」权限；仅查看权限不能导入。选择正确字体族归组，实际字重/斜体以文件解析结果为准。
2. 需要中英配对时创建字体方案，选择两侧实际共有的字重/样式及回退链。先在局部预览中检查中文、英文与标点；预览成功不代表主题已配置。
3. 在「主题应用规则」创建规则，选择实际安装主题、页面范围、字体族或方案。指定文章/页面时搜索并选择稳定内容 ID。填写目标主题真实存在的 class 或标题 ID；例如本地 Earth 文章标题为 `h1.mt-3`，它不是所有主题的通用接口。定位单个标题可用 `#section-introduction`，前提是该页面确实具有此唯一且稳定的 ID。
4. 默认保留主题字重。只有需要且资源实际提供时才选择显式字重；普通规则无法压过内联字体样式。必要时显式开启强制覆盖，只影响本规则的字体声明，仍不保证覆盖其他 !important 或所有子元素。
5. 到「插件 → KhonFontBook → 主题字体应用」勾选「启用主题字体注入」并保存。默认关闭；配置不明时也不会注入。
6. 刷新真实主题页面，检查目标元素的计算字体及实际字体加载。Console 编译区仅检查语法和当前上下文，不读取真实 DOM；CSS 请求 200 也不能单独证明字体已用到目标元素。

规则顺序按 order 升序，同序按 ruleId；只在 CSS 优先级和 importance 相同时，后输出才占优。主题改版、标题 ID 修改、子元素单独字体、iframe/Shadow DOM、图标字体需要分别确认，不提供元素拾取或编辑器功能。

修改、停用规则或关闭注入后，**刷新页面**查看结果；已打开页面不会实时撤回。停用插件后新页面不再加载其样式。浏览器热字体缓存可能继续显示已经缓存的字形，外部同 URL 文件变化还需重校验/重新导入；首次字体 404/网络失败会使用保存的回退链。

插件运行期间主题 HTML 使用 no-store，包括注入关闭时。已有整页缓存/CDN 应清理并尊重该设置；第三方缓存尚未验收。样式资源自身使用不可变内容地址和 ETag，未知/淘汰/重启后未重新发布的地址为 404。

字体或方案被内部或已登记外部引用时，先处理引用再删除资源；停用保留引用。外部引用只能由登记来源撤销或在实际内容迁移后显式确认。删除资源记录保留 Halo 附件，不自动清理用户文件；未登记使用无法检测。

启用且可用的字体、元数据及来源/授权说明可通过公开 API 读取。开放接入不依赖主题注入开关；公开目标 class、来源登记和替换示例见 [接入说明](../../integration/guides/integration-guide.md)，不要把管理凭据写入前端。

0.2.0 发布包在刷新字体库时清理局部预览，需要重新加载；列表刷新不会替你检查主题页面是否已应用字体。发布状态见[版本说明](../../release/guides/release-notes.md)。

运行范围与限制见[完整用户说明](user-guide.md)。
